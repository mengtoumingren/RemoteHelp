# 使用文档

本页面面向测试、联调和产品验证，目标是让你在最短路径内把当前项目跑起来。

## 运行前准备

- 安装 Node.js
- 安装 Android Studio
- 准备一台 Android 模拟器或真机
- 真机联调时，手机和电脑需要在同一局域网

## 配置说明

### 服务端配置

主要环境变量：

- `HOST`：默认 `127.0.0.1`，局域网联调需改 `0.0.0.0`
- `TOKEN_SECRET` / `TOKEN_SECRET_FILE`：令牌签名密钥
- `INVITE_API_KEY` / `INVITE_API_KEY_FILE`：邀请接口鉴权 key
- `ENFORCE_INVITE_API_KEY`：默认 `true`

说明：若未设置 `INVITE_API_KEY`，服务首次启动会自动生成并写入 `INVITE_API_KEY_FILE`。

### 客户端配置

在应用设置页配置：

- 信令服务地址
- 邀请接口 API Key
- STUN / TURN 配置

推荐服务地址：

- 生产：`wss://<你的域名>/ws`
- 模拟器联调：`ws://10.0.2.2:3000/ws`（仅 Debug）
- 真机联调：`ws://<宿主机局域网IP>:3000/ws`（仅 Debug）

## 服务端使用

在仓库根目录执行：

```bash
cd server
npm install
npm run dev
```

启动后可以先检查两个接口：

```text
GET http://localhost:3000/health
GET http://localhost:3000/config
```

如果使用真机，请把 `localhost` 换成宿主机局域网 IP。

## 客户端使用

1. 使用 Android Studio 打开 `clients/android/mainproject`
2. 选择 `mainproject` 模块运行到设备
3. 首次启动时按提示授予相机、麦克风、通知、悬浮窗、无障碍和屏幕采集相关权限
4. 在设置里确认信令地址与邀请接口 API Key

常用地址：

- 模拟器：`ws://10.0.2.2:3000/ws`
- 真机：`ws://<宿主机局域网IP>:3000/ws`

## 主应用流程

主应用当前支持的体验链路是：

1. 子女端创建协助请求
2. 生成带签名的 Deep Link / token
3. 长辈端打开链接进入验证
4. 双方完成视频核验
5. 长辈端授权后进入远程协助
6. 子女端发起远程操作，长辈端执行屏幕采集和无障碍控制

## 用户层面使用说明

本章节面向非技术用户，按角色给出实际操作步骤。

### 协助方（子女）怎么操作

1. 打开应用，切换到“我来协助”。
2. 输入被协助人的姓名与手机号，点击创建协助请求。
3. 将生成的协助链接通过微信、短信等方式发给对方。
4. 等待对方进入后，先完成视频核验。
5. 核验通过后进入远程协助页面，观察对方屏幕状态。
6. 按需发送点击、滑动、返回等操作指令。
7. 协助完成后主动结束会话。

### 被协助方（长辈）怎么操作

1. 点击收到的协助链接，打开 RemoteHelp。
2. 确认协助方信息后进入视频核验页面。
3. 允许相机和麦克风权限，完成身份核验。
4. 进入远程协助阶段后，按提示授权：
	- 屏幕采集权限
	- 无障碍服务权限
5. 协助过程中可随时口头沟通，确认每一步操作。
6. 协助结束后关闭屏幕共享，并退出会话。

### 协助前检查清单

- 双方网络稳定（建议 Wi-Fi）。
- 双方手机电量充足。
- 被协助方提前开启系统权限入口，避免中断。
- 涉及支付、验证码、密码输入时，建议由被协助方本人完成。

### 会话安全建议

- 仅对可信联系人发起或接受协助。
- 不在公共群聊里公开协助链接。
- 会话结束后检查是否已关闭屏幕共享与无障碍服务。
- 发现异常操作时，立即结束会话并更改关键账号密码。

## 常见问题

### 1. 模拟器连接不上服务端

- 确认后端已经启动
- 确认信令地址是 `ws://10.0.2.2:3000/ws`
- 检查防火墙是否拦截了 3000 端口

### 2. 真机无法加入房间

- 把信令地址改成宿主机局域网 IP
- 确认手机和电脑在同一局域网
- 确认电脑本机 3000 端口可访问

### 3. 看不到视频或麦克风没声音

- 检查相机和麦克风权限
- 检查设备是否占用了摄像头
- 确认浏览器或其它 App 没有独占音频设备

### 4. 远程控制没有生效

- 先打开无障碍服务
- 先授予屏幕采集权限
- 确认目标端和控制端在同一房间
